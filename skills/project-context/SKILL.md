# project-context

まず `/AGENTS.md` を読むこと。本Skillは重複させず、判断が必要な場面での指針だけを持つ。

## P0スコープの判断

「これはP0か」で迷ったら、以下に無いものはP0外。

**P0に入る**: 複数写真選択 / 任意テキスト入力 / 意味理解 / レイヤー候補抽出 /
象徴要素の自動選定 / x・y・scale・layerIndex の自動構成 / 処理段階表示 /
3D完成プレビュー（Read Only、回転・Zoom・正面Reset） / 2D編集（位置・拡大縮小・差し替え・前後変更） /
編集後のロジックベース再描画 / 2.5D物理PoC / 公開Deploy

**P0外（勝手に作らない）**: 複数構成案 / Undo・Redo / AI初稿へ戻す / 差し替え候補の追加取得 /
Exploded View / 詳細な組み立てガイド / 凹凸表現・多色化・スタイル加工 / 注文・配送・決済 /
Login / 作品一覧 / 長期保存 / 3D Preview上での直接編集 / Layer画像の回転編集

## 実装開始条件

**担当本人が「Input → 処理 → Output」を中心に自分の担当処理を説明できれば実装開始してよい。**
PMの個別承認は原則不要。担当内部だけで完結する実装は承認を待たない。

説明できる状態にしておくこと:

- 責任範囲 / 入力 / 処理 / 出力 / 依存先
- 他担当と接する契約（Artwork Data / API / Asset）
- 主要な Error / Timeout の扱い
- 他担当未完成時に使うMockと、単独での動作確認方法
- 完成条件と、担当間の接続確認方法

**Mermaid構成図と sequenceDiagram の2枚固定は必須ではない。** 文章だけで把握しづらい箇所に
必要な図だけ作る。作った図はソースで終わらせず、Renderして本人が目視確認する。
AIに作らせた図・設計をそのまま正としない。

「実装前設計整理_任意テンプレート」は整理の補助。記入自体を開始条件にしない。

### 開始前に共有が必要なもの

以下へ影響する変更は担当内で確定させず、**公開チャンネルで共有してから**進める。

共通技術設計 / Artwork Data / API・Protocol / MVP Scope / 他担当の実装前提 / 費用

## 迷ったときの分岐

- Top Levelを増やしたい → 独立したBuild / Deploy / Runtime単位か確認する。違うなら作らない
- `physical-output/` を作りたい → Physical Output担当のPoC結果を待つ
- 共通Schemaを変えたい → 実装せず、影響範囲を提示して公開チャンネルへ
- Backend内部だけの話 → Backend担当と相談して進めてよい
- 判断がつかない → 作らずに保留し、確認を求める。「たぶん必要」で先に固定しない
